# Priorities for office management

## What comes first

1. **Trips in the next 4 weeks** that are not prepared yet.
2. **Missing travel requests**: a trip is coming but there is no travel number (no DRA). Do not book. Remind the traveller.
3. **Deadlines**: registration, early-bird, call-for-papers dates from emails and the event overview.
4. **Questions before leave**: if a traveller will be on leave, ask your questions before the leave starts.
5. Trips further away: prepare options, no rush.
6. Reminders for paper requests (training, procurement).

## One task per trip

- The same trip can arrive by email, as a forwarded DRA and on Mattermost. Keep **one** task and add the new information to it.
- If a trip is cancelled, mark the task `cancelled` and stop all work on it (no more searches, no messages about it).
- If someone else may go instead, write that down as an open question.

## Task status words

| Status | Meaning |
|---|---|
| `open` | We know about it, but nobody has checked it yet. |
| `needs_info` | We asked the traveller something and wait for the answer. |
| `waiting_for_request` | No travel number yet: do not book. |
| `ready_to_book` | Travel number present (DRA). We can prepare options; a person books. |
| `cancelled` | It does not happen. Stop all work on it. |
| `done` | Booked or finished. |

## Task kinds

| Kind | Meaning |
|---|---|
| `trip` | A business trip. |
| `leave` | Someone is on leave (dates only). |
| `estimate` | Only a cost estimate is needed, there is no travel request yet. |
| `reminder` | Something to remember (e.g. a paper request), nothing to book. |
| `open_question` | A question somebody must decide (e.g. who goes to an event). |

## Leave

Write every approved leave as a task of kind `leave` with the dates. Use it to plan when to ask questions.
For a leave, check the event overview for events during the leave, and note them.
